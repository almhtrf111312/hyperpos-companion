# رسالة القناة: ما يهم المستخدم فقط + ملف التطبيق جاهز

## المشكلة
رسالة القناة تأخذ ملاحظات التحديث الداخلية كما هي، فتذكر لوحة Boss وفرع public-release وطريقة الربط، وهذه أمور لا تخص المستخدمين. والرابط يفتح GitHub بدل إرسال الملف.

## ما سيتغير

### 1. ملاحظات منفصلة للمستخدمين
- لكل إصدار في سجل التغييرات قسم جديد «للمستخدمين» مقسم إلى: **جديد**، **تحسينات**، **إصلاحات**.
- رسالة القناة تأخذ هذا القسم فقط، ولا ترسل الملاحظات الداخلية أبداً.
- إن لم يوجد قسم للمستخدمين، تُحذف تلقائياً أي جملة تذكر: Boss، GitHub، فرع، public-release، Telegram، بوت، خادم، SQL، Build.
- كتابة نص الإصدار الحالي 1.4.0 للمستخدمين، مثل:
  - جديد: عند قبض مبلغ أقل من الفاتورة، يمكن تسجيل الفرق مصروفاً باسم «فرق سعر» مع رقم الفاتورة والأصناف، أو تسجيله ديناً على العميل.
- بدءاً من الآن، كل تعديل أضيف له جملة للمستخدمين بلغة بسيطة بجانب الملاحظة الداخلية.

### 2. شكل رسالة القناة
```text
تحديث جديد - Flow POS Pro
الإصدار 1.4.0

جديد:
• ...
تحسينات:
• ...
إصلاحات:
• ...
```
بدون ذكر لوحة الإدارة أو GitHub أو الفروع.

### 3. إرسال ملف التطبيق مباشرة إلى القناة
- عند الدفع إلى فرع النشرة العامة: يُبنى ملف Android (APK) تلقائياً، ثم يُرسل **الملف نفسه** إلى القناة مع الرسالة أعلاه كوصف له.
- يُحفظ نفس الملف أيضاً في صفحة الإصدارات بـ GitHub كأرشيف (لا يظهر رابطها في القناة).
- زر النشر في لوحة Boss يرسل الرسالة النظيفة نفسها.

## تفاصيل تقنية
- `public/changelog.json`: حقل اختياري `public: { new:[], improved:[], fixed:[] }` لكل إصدار.
- `.github/workflows/telegram-public-release.yml`: خطوات setup-node + Java 17 + `npm ci && npm run build && npx cap sync android && ./gradlew assembleRelease`(أو Debug إن لم تتوفر أسرار التوقيع)، ثم `sendDocument` بـ multipart مع caption (حد 1024 حرف، والباقي برسالة تالية)، ثم `softprops/action-gh-release` للأرشيف. تنسيق النص بسكربت node صغير مع الفلترة الاحتياطية.
- `supabase/functions/publish-telegram-release/index.ts` و`BossReleasesPanel.tsx`: استخدام نفس الحقل والفلترة.
- توقيع APK: إن أردت ملفاً يُحدّث فوق النسخة المثبتة يجب إضافة أسرار مفتاح التوقيع (keystore) في GitHub؛ بدونها يُرسل ملف تجريبي قد يتطلب حذف النسخة القديمة.
- رفع الإصدار وسجل التغييرات حسب قاعدة المشروع.
