# خطة الفحص الشامل لتطبيق Flow POS Pro

## الهدف
فحص كامل لخمسة محاور: الحماية، دورة المال (شركاء، منتجات، بيع، دين، مصاريف)، المنطق الحسابي، ربط الأزرار، والتصميم. الناتج: تقرير عربي مفصل جداً (المشكلة، مكانها، خطورتها، سببها، الحل المقترح، وهل تحتاج موافقتك)، ثم إصلاح على دفعات آمنة.

قيود ثابتة: لا لمس للمستودعات وتحويل العهدة (مجمّدة). لا تغيير لأي معادلة مالية دون موافقتك. لا عمليات بيع أو شراء أو دفع على بياناتك الحقيقية. أي تغيير يرفع رقم الإصدار ويُكتب في سجل التغييرات.

## ثانياً: مراحل الفحص التفصيلي

### المرحلة 1 — الحماية
- مراجعة قواعد الوصول لكل جدول (37 جدولاً): من يقرأ، يضيف، يعدّل، يحذف؛ والتأكد أن الكاشير يرى بيانات مالكه فقط ولا يرى سعر الجملة أو بيانات الشركاء.
- مراجعة كل دوال الخادم (15 دالة): التحقق من هوية المستدعي، صلاحيته، وعدم تسريب بيانات في السجلات.
- الدوال الحساسة (حذف مستخدم، تغيير كلمة مرور، إلغاء رخصة): التأكد أنها للمدير العام فقط.
- تشغيل فحص أمني جديد لأن النتائج الحالية قديمة.
- مراجعة التخزين على الجهاز: البيانات المشفرة، ومسح بيانات المستخدم السابق عند تغيير الحساب.

### المرحلة 2 — دورة المال والربط بين الأقسام
تتبّع كل عملية من الزر حتى قاعدة البيانات، والتأكد أن كل الأرقام المرتبطة تتحدث معاً:

```text
بيع نقدي  -> فاتورة + خصم مخزون + حركة مخزون + ربح + حصص الشركاء + الصندوق + الوردية
بيع آجل   -> ما سبق + دين + رصيد العميل + الدفعة الأولى
سداد دين  -> الدين + الفاتورة + رصيد العميل + الصندوق
استرداد   -> عكس المخزون + عكس الربح + عكس حصص الشركاء + حذف/تعديل الدين
مصروف     -> الصندوق + توزيع على الشركاء + التقارير
شراء      -> كمية المنتج + متوسط التكلفة + المصروف/الدين للمورد
شطب دين   -> رأس المال + أثر على الشركاء
```
لكل مسار: هل يعمل بدون إنترنت؟ هل يمنع التكرار عند إعادة المزامنة؟ هل يُعكس بالكامل عند الاسترداد أو الحذف؟

### المرحلة 3 — المنطق الحسابي
- مطابقة كل معادلة في التطبيق مع ملف المعادلات المالية المعتمد: الربح الإجمالي = المجموع - الخصم - التكلفة، الضريبة ليست ربحاً، الصافي، رأس المال، حصص الشركاء.
- تعدد العملات (دولار/ليرة تركية/ليرة سورية): التحويل، الخصم بالعملة الأجنبية، التقريب لخانتين.
- مقارنة أرقام لوحة التحكم والتقارير والصندوق مع بعضها، واستبعاد الفواتير المستردة والملغاة.
- فحص المخزون السالب ومتوسط التكلفة.
- البحث عن حسابات مكررة في أكثر من مكان قد تعطي نتائج مختلفة.
- الفحص يتم بقراءة الكود وبيانات اختبار وهمية فقط.

### المرحلة 4 — ربط الأزرار
- المرور على كل صفحة (نقطة البيع، الفواتير، الديون، العملاء، المصاريف، الشركاء، الصندوق، الورديات، المشتريات، المنتجات، التقارير، الإعدادات، المظهر، لوحة المدير العام).
- لكل زر: هل يعمل؟ هل يمنع النقر المزدوج؟ هل يظهر للمستخدم المسموح له فقط؟ هل يعطي رسالة نجاح/فشل واضحة؟

### المرحلة 5 — التصميم
- لقطات للشاشات على الهاتف والكمبيوتر، بالوضع الليلي والنهاري.
- فحص: نصوص مقطوعة، أزرار صغيرة، تداخل، اتجاه العربية، الأرقام الغربية، الألوان المثبتة يدوياً، توحيد الأشكال.

## ثالثاً: التقرير النهائي
ملف عربي قابل للتحميل يحتوي لكل مشكلة: الرقم، القسم، الوصف، الخطورة (حرجة/عالية/متوسطة/منخفضة)، المكان، مثال على أثرها بالأرقام، الحل، وهل يحتاج موافقتك (أي شيء يمس المعادلات المالية).

## رابعاً: ترتيب الإصلاح بعد التقرير
1. أخطاء التطبيق (البند 1) + تسريب السجلات (البندان 2 و3) — فوري وآمن.
2. المشاكل المالية الحرجة — بعد عرضها عليك والموافقة.
3. الحماية المتبقية.
4. الأزرار.
5. التصميم.
كل دفعة برقم إصدار مستقل لتسهيل التراجع.
