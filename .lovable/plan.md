# خطة: لوحة Boss العملية + التحديثات والإشعارات عن بُعد

## الهدف
- إرسال إشعارات لكل مستخدمي التطبيق من لوحة الـ Boss (رسائل جاهزة أو نص حر).
- إيقاف النسخ القديمة: تحديث إجباري مع مهلة (مثلاً 3 أيام) ثم قفل التطبيق حتى التحديث، مع رابط تحميل تحدده أنت.
- معرفة إصدار التطبيق الذي يعمل عليه كل مستخدم.
- زر «تحديث التطبيق» في صفحة التواصل مع المطور يفتح رابط قناة Telegram.
- إعادة ترتيب لوحة الـ Boss لتكون عملية وسريعة (جداول كثيفة، فلاتر، إجراءات بنقرة واحدة).

## المرحلة 1: البيانات في الخادم
- جدول للإشعارات العامة: العنوان، النص، النوع (معلومة / تحذير / تحديث إجباري)، الرابط، تاريخ الانتهاء، فعال أم لا.
- إعدادات الإصدارات: أقل إصدار مسموح، آخر إصدار، مهلة السماح، رابط التحديث، رابط Telegram.
- تسجيل إصدار التطبيق والمنصة وآخر ظهور لكل مستخدم.
- صلاحيات: الـ Boss فقط يكتب، والجميع يقرأ الإشعارات الفعالة.

## المرحلة 2: لوحة الـ Boss
- تبويبات: المستخدمون، الإشعارات، الإصدارات، التراخيص.
- جدول المستخدمين يعرض: الاسم، المتجر، الإصدار، المنصة، آخر ظهور، حالة الترخيص، مع فلتر «نسخة قديمة».
- محرر إشعار مع رسائل جاهزة (تحديث متوفر / تحديث إجباري خلال 3 أيام / صيانة) ومعاينة قبل الإرسال.
- إعدادات الإصدار وأزرار سريعة: «اجعل هذا الإصدار إجبارياً».

## المرحلة 3: داخل التطبيق
- عند الفتح ومع كل اتصال: إرسال الإصدار وجلب الإشعارات وإعدادات الإصدار.
- إشعار نظام على Android، وإن تعذر يظهر تنبيه داخل التطبيق.
- نافذة تحديث إجباري تعرض الأيام المتبقية، ثم شاشة قفل بزر التحديث بعد انتهاء المهلة.
- دون اتصال: آخر حالة محفوظة تبقى سارية.

## المرحلة 4: صفحة التواصل مع المطور
- زر «تحديث التطبيق» وزر Telegram يقرآن الروابط من الإعدادات.
- اختبار السيناريوهات: إشعار عادي، تحديث إجباري خلال المهلة، بعد المهلة، ودون اتصال.
- رفع رقم الإصدار وسجل التغييرات.

## ملاحظات تقنية
- تغييرات قاعدة البيانات بإذنك المسبق حسب قواعد المشروع.
- الإشعارات المحلية عبر Capacitor LocalNotifications (تتطلب `npx cap sync` بعد السحب).
- إشعارات الدفع الحقيقية والتطبيق مغلق تحتاج Firebase؛ خارج هذه الخطة إلا إذا طلبتها.
- عدم لمس ملفات المستودعات المجمدة.
